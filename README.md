# DependencyVisualisation

## Общее описание

CLI-инструмент для анализа зависимостей пакетов Rust (Cargo), вариант № 2.
На этапе 4 он отвечает на вопрос «Какие пакеты зависят от заданного пакета?».
Например, если `B` указывает `A` в своих зависимостях, поиск для `A` на глубине 1 выдаст `B`.
У самого `A` список зависимостей может быть пустым.

Программа читает весь выбранный репозиторий и для каждого пакета составляет список
его непосредственных потребителей. Затем BFS этапа 3 обходит эти связи по уровням
без рекурсии. Глубина корня равна 0. На глубине 1 видны прямые потребители,
на глубине 2 добавляются их потребители. Пакеты на границе глубины входят в результат.
Каждый найденный пакет выводится один раз в алфавитном порядке с выбранной версией.
Корень исключается из списка, в том числе при циклах и петлях.

### Источники и выбор версии

В тестовом режиме источником служит JSON-файл со списками **обычных** зависимостей.

```json
{"A": [], "B": ["A", "A"]}
```

Здесь у `A` один потребитель — `B`. Имена состоят из заглавных латинских букв (`[A-Z]+`).
Каждый упомянутый пакет должен иметь собственную запись. Пустой список означает отсутствие
прямых зависимостей. Тестовым пакетам назначается условная версия `1.0.0`.

В режиме Cargo укажите HTTP(S)-адрес полного снимка индекса в формате `tar.gz`.
Снимок содержит файлы JSONL по путям Cargo (например, `se/rd/serde`) в корне архива
или в одном общем каталоге. Адрес отдельной записи sparse-индекса подходит только
для получения зависимостей одного пакета. Поиск всех потребителей требует полного индекса.
За запуск архив передается по HTTP один раз и разбирается потоком без распаковки на диск.
В памяти сохраняются выбранные версии и обратные связи. Размер снимка влияет на время запуска
даже при небольшой глубине поиска. [Формат индекса Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html)

Для каждого пакета выбирается максимальный стабильный неотозванный релиз по SemVer.
При одинаковом приоритете используется первая подходящая запись. Пакеты без такого релиза
исключаются. Учитываются обычные, сборочные, тестовые, необязательные и платформенные
зависимости выбранного релиза внутри этого индекса. Для переименованной зависимости
используется имя из поля `package`. Поиск выполняется по имени пакета. Ограничение `req`
сохраняется в метаданных и не участвует в выборе версии. [SemVer 2.0.0](https://semver.org/)

### Основные функции

| Пакет | Назначение |
| --- | --- |
| `config` | `MustLoadConfig` читает INI и проверяет пять обязательных параметров. |
| `cargo` | `OpenIndex` открывает HTTP-поток, `WalkSnapshot` перебирает записи снимка. `LoadVersions` читает версии одного пакета по sparse-URL. Оба источника используют общий разбор JSONL. |
| `testrepo` | `Load` проверяет тестовый граф, `LoadVersions` возвращает пакет, `VisitVersions` перечисляет все вершины. |
| `reverse` | `New` создает индекс, `AddVersions` добавляет входящие связи выбранного релиза, `LoadVersions` возвращает его потребителей. |
| `analyzer` | `CompareVersions` сравнивает SemVer, `SelectVersion` выбирает релиз. `New` принимает источник, `PackageDependencies` читает пакет, `BuildGraph` выполняет BFS. |
| `domain` | `PackageVersion` и `Dependency` хранят метаданные. `PackageID` и `Graph` описывают вершины и ребра. |
| `main` | `run` выбирает источник и запускает обход, `printDependents` выводит результат. |

Данные индекса получает и разбирает сама программа средствами стандартной библиотеки Go.
Для чтения настроек используется `gopkg.in/ini.v1`. Подробности функций доступны через Godoc.

## Настройки

Пример из `tests/graph.ini` для запуска из корня репозитория.

```ini
[visualizer]
package_name = E
repository = tests/graph.json
test_mode = true
ascii_tree = false
max_depth = 3
```

| Параметр | Описание |
| --- | --- |
| `package_name` | Имя искомого Cargo-пакета или вершины тестового графа. |
| `repository` | HTTP(S)-URL снимка индекса Cargo или путь к JSON-файлу тестового репозитория. |
| `test_mode` | `true` выбирает тестовый файл, `false` выбирает снимок Cargo. |
| `ascii_tree` | Обязательный булев параметр. Вывод дерева предусмотрен на этапе 5. |
| `max_depth` | Максимальная глубина BFS, целое число от 0. При 0 список потребителей пуст. |

Путь к INI задается флагом `-config`, по умолчанию используется `tests/example.ini`.
Относительные пути отсчитываются от рабочего каталога. Ошибки INI вызывают `panic`.
Неизвестный корень, ошибки источника и анализа дают сообщение в `stderr` и код 1.
При успехе результат выводится в `stdout`, код завершения равен 0.

## Сборка и тесты

Требуются Go 1.26.4 или новее и Make. Из корня репозитория выполните

```sh
make build
make test
```

Приложение собирается в `bin/visualiser`. Тесты рядом с исходниками проверяют настройки,
SemVer, прямой и обратный обход, вывод CLI, чтение снимка через локальный HTTP-сервер
и обработку поврежденных данных. Для запуска тестов подключение к crates.io не требуется.

## Примеры использования

**Тестовый граф.** Запуск с готовым INI

```sh
make run CONFIG=tests/graph.ini
```

Результат для `E` на глубине 3

```text
Обратные зависимости пакета E 1.0.0:
  A 1.0.0
  B 1.0.0
  C 1.0.0
  D 1.0.0
```

Для остальных случаев измените `package_name` и `max_depth` в копии `tests/graph.ini`
и передайте путь к ней через `CONFIG`. Во всех строках используется один `tests/graph.json`.

| Корень | Глубина | Вывод | Что демонстрирует |
| --- | ---: | --- | --- |
| `Z` | 3 | Не найдены. | Изолированный пакет. |
| `E` | 0 | Не найдены. | Обход ограничен корнем. |
| `E` | 1 | `D` | У конечной вершины есть потребитель. |
| `E` | 2 | `B, C, D` | И `B`, и `C` зависят от `D`. |
| `E` | 3 | `A, B, C, D` | Два пути ведут к `A`, он выводится один раз. |
| `A` | 3 | `C` | Цикл между `A` и `C` замыкается на корне. |
| `D` | 1 | `B, C` | Петля `D → D` исключена из ответа. |
| `B` | 1 | `A` | Две записи `B` в зависимостях `A` дают одного потребителя. |

**Индекс Cargo.** В `tests/example.ini` указан снимок crates.io и пакет `serde`.
Запуск с полным индексом требует сети. Список зависит от содержимого снимка.

```sh
./bin/visualiser -config tests/example.ini
```

**Ошибка конфигурации.** Запуск с недопустимым именем пакета

```sh
make run CONFIG=tests/invalid_package.ini
```

Ожидаемая ошибка — `неверное значение package_name: "bad/name"`.
Для остальных параметров в `tests` есть примеры `invalid_repository.ini`,
`invalid_test_mode.ini`, `invalid_ascii_tree.ini` и `invalid_max_depth.ini`.
