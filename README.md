# DependencyVisualisation

## Общее описание

CLI-инструмент для визуализации зависимостей пакетов Rust (Cargo), вариант № 2.
Стрелка `A → B` означает, что пакет `A` объявляет зависимость от `B`.
Программа строит граф обходом в ширину (BFS) без рекурсии, записывает его на языке D2
и открывает изображение SVG. Двойная рамка обозначает корневой пакет. При `ascii_tree = true`
тот же граф выводится в терминал в виде дерева.

В обычном режиме программа сама читает JSONL-записи по HTTP из sparse-индекса Cargo.
Для каждого имени она выбирает максимальный стабильный неотозванный релиз по SemVer.
При равном приоритете берется первая подходящая запись. Для переименованной зависимости
используется имя из поля `package`. Все имена ищутся в указанном индексе.
Граф охватывает объявленные зависимости, включая сборочные, тестовые, необязательные
и платформенные. Выбор версии выполняется независимо для каждого пакета, без разрешения
ограничений `req`, feature-флагов и `Cargo.lock`.
[Формат индекса Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html)

В тестовом режиме источником служит локальный JSON, например `{"A":["B"],"B":[]}`.
Имена состоят из заглавных латинских букв. Каждый упомянутый пакет имеет свою запись
и получает условную версию `1.0.0`. Дубликаты одной связи дают одну стрелку.
Циклы, петли и общие зависимости сохраняются. В ASCII-дереве каждый пакет раскрывается
один раз на кратчайшем пути от корня. Метка `(*)` обозначает дополнительную ссылку на него.

## Функции и настройки

| Пакет | Назначение |
| --- | --- |
| `config` | `MustLoadConfig` читает и проверяет пять обязательных значений INI. |
| `cargo` | `LoadVersions` получает и разбирает запись sparse-индекса по имени пакета. |
| `testrepo` | `Load` проверяет тестовый граф, `LoadVersions` возвращает зависимости вершины. |
| `domain` | `PackageVersion` и `Dependency` хранят метаданные. `PackageID` и `Graph` задают вершины и ребра. |
| `analyzer` | `CompareVersions` сравнивает версии, `SelectVersion` выбирает релиз, `PackageDependencies` читает пакет, `BuildGraph` выполняет BFS. |
| `visualize` | `D2` описывает вершины и ребра, `WriteTree` выводит дерево, `Show` сохраняет D2, запускает рендерер и открывает SVG. |
| `main` | `run` выбирает источник по INI и передает построенный граф средствам вывода. |

Обратный поиск по полному снимку индекса (пакет `reverse`, методы `OpenIndex`,
`WalkSnapshot` и `VisitVersions`) демонстрируется в ветке `etap4`.
Этап 5 использует обычные зависимости и загружает только записи, нужные для обхода.
Настройки читаются через `gopkg.in/ini.v1`. Зависимости пакетов получает стандартная библиотека Go.

Пример из `tests/example.ini`

```ini
[visualizer]
package_name = num-integer
repository = https://index.crates.io
test_mode = false
ascii_tree = true
max_depth = 2
```

| Параметр | Описание |
| --- | --- |
| `package_name` | Имя корня в выбранном репозитории. |
| `repository` | Базовый HTTP(S)-URL sparse-индекса Cargo или путь к тестовому JSON. |
| `test_mode` | `true` выбирает локальный JSON, `false` выбирает индекс Cargo. |
| `ascii_tree` | `true` дополнительно печатает дерево в терминале. SVG открывается при обоих значениях. |
| `max_depth` | Максимальная глубина обхода. При 0 виден только корень, при 1 добавляются прямые зависимости. |

Флаг `-config` задает путь к INI, по умолчанию используется `tests/example.ini`.
Относительные пути отсчитываются от рабочего каталога. Ошибки INI вызывают `panic`.
При ошибке анализа, рендеринга или открытия изображения CLI завершает работу с кодом 1
и пишет причину в `stderr`.

## Сборка и запуск тестов

Требуются Go 1.26.4 или новее и Make. Для показа диаграмм нужны команда `d2` в `PATH`
и графическая сессия. В macOS SVG открывается в Safari, в Linux — через `xdg-open`,
в Windows — приложением для SVG. Для независимого сравнения в последнем примере нужен Cargo.
[Установка D2](https://d2lang.com/tour/install/)

```sh
make build
make test
```

Исполняемый файл создается в `bin/visualiser`. Тесты CLI используют локальные источники и проверяют граф до передачи просмотрщику.

## Примеры использования

### Тестовый граф с циклом

```sh
make run CONFIG=tests/graph.ini
```

На глубине 3 граф содержит 5 вершин и 7 направленных ребер. Видны петля `D → D`,
два пути к общей вершине `D` и цикл `A → C → A`.
В терминале перед путем к SVG появляется дерево

```text
A 1.0.0
|-- B 1.0.0
|   `-- D 1.0.0
|       |-- D 1.0.0 (*)
|       `-- E 1.0.0
`-- C 1.0.0
    |-- D 1.0.0 (*)
    `-- A 1.0.0 (*)
```

После успешного запуска строка `SVG:` содержит путь к изображению.
Рядом с `graph.svg` находится исходник `graph.d2`. Каждый запуск получает свой временный каталог.
При ошибке D2 сообщение указывает путь к исходнику, при ошибке просмотра — к готовому SVG.

Для проверки ошибок INI в `tests` есть отдельный пример для каждого параметра.
Так, `make run CONFIG=tests/invalid_package.ini` сообщает о недопустимом имени `bad/name`.

### Три пакета crates.io и сравнение с Cargo

Каждая команда открывает диаграмму своего пакета и выводит дерево на глубине 2.

```sh
./bin/visualiser -config tests/autocfg.ini
./bin/visualiser -config tests/num-traits.ini
./bin/visualiser -config tests/example.ini
```

Результаты 20 ноября 2026 года на macOS arm64 с Cargo 1.99.1 и D2 0.9.0.
В таблице приведены все ребра двух выводов. Корень входит в граф даже при отсутствии ребер.

| Корневой пакет | Ребра визуализатора | Ребра `cargo tree` |
| --- | --- | --- |
| `autocfg 1.5.1` | Только корень | Только корень |
| `num-traits 0.2.19` | `num-traits → autocfg`, `num-traits → libm`, `libm → no-panic` | `num-traits → autocfg` |
| `num-integer 0.1.47` | `num-integer → num-traits`, `num-traits → autocfg`, `num-traits → libm` | `num-integer → num-traits`, `num-traits → autocfg` |

Все общие пакеты совпали по версии. У `num-traits` сборочная зависимость `autocfg` обязательна,
а `libm 0.2.16` объявлена как `optional` и выключена в стандартном наборе возможностей.
Поэтому `cargo tree` показывает только ветвь `autocfg`. Визуализатор также видит в индексе
тестовую зависимость `libm → no-panic 0.1.37`. Для корня `num-traits` она попадает на уровень 2,
для `num-integer` — на уровень 3, за предел заданной глубины.
[Запись num-traits](https://index.crates.io/nu/m-/num-traits) · [Запись libm](https://index.crates.io/li/bm/libm)

Для повторения сравнения создайте временный Rust-проект с теми же версиями корней.
Команды используют стандартные возможности пакетов и ту же глубину, что и три INI.

```sh
demo=$(mktemp -d)
cargo new --lib --vcs none "$demo/comparison"
manifest="$demo/comparison/Cargo.toml"
cargo add --manifest-path "$manifest" autocfg@=1.5.1 num-traits@=0.2.19 num-integer@=0.1.47
cargo tree --manifest-path "$manifest" --depth 2 --charset ascii --no-dedupe \
  -p autocfg -p num-traits -p num-integer
```

Cargo отмечает сборочную ветвь строкой `[build-dependencies]`. Параметр `--no-dedupe`
позволяет увидеть каждое из трех деревьев целиком при совместном выводе.
При последующих запусках визуализатор берет версии из актуального индекса.
[Справка cargo tree](https://doc.rust-lang.org/cargo/commands/cargo-tree.html)
